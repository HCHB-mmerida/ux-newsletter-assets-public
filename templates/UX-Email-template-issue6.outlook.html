The UX advantage
AI can build the interface, UX makes sure it matters
Article by Marty Merida
AI can support UX execution
As agentic AI takes on more implementation work, it is important to be clear about what that changes for UX. Our design system and UX skill files give AI practical guidance to follow while it codes a UI: established components, accessibility expectations, interaction patterns, and other proven practices. They help carry UX standards into generated work, but they do not independently discover what users need or design a good experience for them. Essentially, AI creates the UI, not the UX.
What AI can—and cannot—do well
AI can help the UX team explore ideas, summarize research, draft content, generate prototypes, and apply consistent patterns. But it cannot replace direct user research, empathy for the people behind the personas, or the product judgment needed to decide which problems matter and what the product should do. Those decisions come from understanding users’ goals, workflows, constraints, and context—and then evaluating whether a proposed solution actually helps them. There are additional areas UX would like to shift focus to in the coming years that AI is not great at doing today, such as progressive disclosure, personalization, gamification, the feel of thoughtful animations, and automating manual experiences where possible.
Our value as the landscape shifts
Our team connects what we learn about users to product direction, shapes clear experiences, and gives AI useful guidance to support implementation. The more quickly AI can build, the more important it is to make sure we are building the right thing.

For further reading, see Google’s People + AI Guidebook and Nielsen Norman Group’s AI for UX: Getting Started.

Design systems
Bringing the HCHB Figma Design System and Telerik into parity
UX work led by Marty Merida and contributed to by the entire UX team
Aligning design components with Telerik
Wes, Ezequiel, Lonnie, Tessa, Carla, and Marty worked together to bring the components in our Figma Design System Components library into congruity with the Telerik components. We identified several missing components that are now accounted for in our HCHB library. Many of these new component values have AI integrations as well to showcase usage variants.
The list of components added to the Figma library are as follows:
  • Chat
  • Tree view
  • Dropdown tree
  • Floating action button (FAB)
  • Grid cell and row select
  • Masked text box
  • Progress bar and Chunk progress bar
  • Date/Time Picker
  • Date range picker
  • Breadcrumb
  • Floating action button
  • Grid
  • List box
  • List view
  • Masked text box
Connecting design and code
With the design components mapped to Telerik, designers and developers can work from a shared foundation within Figma and Figma MCP. That alignment makes it easier to identify the intended component, understand its expected behavior, and keep experiences consistent across design and development, allowing more seamless integration for automated AI UI work.
Giving AI a clearer reference
The updated Design System Components file also gives AI a visual design reference when it creates components based on Telerik assets. UX skill files and design system guidance help AI apply our established patterns during implementation, while UX expertise continues to shape the user needs and decisions behind the experience.
Set consistent rules for visual depth
Standardized shadow effects and usage guidance, including reverse elevation, clarify how components should appear in relation to one another and support a more cohesive interface.
Build a structure for reusable patterns
Work began on organizing the Design System into foundations, components, patterns, and page layouts. This creates a clearer path for expanding reusable guidance for navigation, search, filtering, and common workflows—helping teams reduce duplicated effort and build accessible experiences more efficiently.

Design systems
Figma Make Kit: Bringing the HCHB Design System into AI-assisted design
UX work led by Wes Pallister
Giving Figma Make the HCHB context
Figma Make can turn ideas into working prototypes quickly. To help those prototypes reflect how HCHB products look and behave, we are building the HCHB DS Kit: a shared resource that brings our internal Design System and UX guidance into the Make workflow.

The kit brings together guidance for foundations, interaction patterns, and component usage. It also includes an inventory of our component library, represented as built-in React facsimiles that Make can draw on when generating interfaces.
Making standards easier to apply
When someone includes the HCHB DS Kit in Figma Make, it gives the tool more context for generating screens aligned with our application UI, usability standards, and brand. Designers and product teams can start from familiar components and established patterns, instead of recreating them or relying on memory.

The guidance is intended to support consistent decisions across layouts, interactions, and component use. Teams can still shape the experience around the specific user need, while beginning with a clearer shared foundation.
Helping teams move from idea to prototype
A common kit can make early exploration faster and make prototypes easier to discuss across UX, Product, and Engineering. With HCHB patterns and components close at hand, teams can focus more of their time on the workflow, content, and usability questions a prototype needs to answer.

The kit is a practical way to bring our design standards into AI-assisted creation—and to help Make outputs start closer to the HCHB experience we want to deliver.
Scheduling
A map-first view connects visits, workers, and schedules
UX work led by Ezequiel “Zeque” Dominguez
Compare coverage at a glance
The initial Scheduler Map View exploration pairs geographic visit markers with a compact worker schedule panel. Worker indicators, visit severity, and daily workload summaries help schedulers compare assignments and monitor selected workers.
Coordinate changes across the map and schedule
Synchronized selections and scheduling conflict and capacity feedback keep key details in view while schedulers consider reassignments—without switching between multiple calendars.
Respond to changing coverage needs
By bringing location and workload information together, the concept could help schedulers manage call-outs, weekend on-call assignments, and emergent visits while making more informed decisions about workload balance and travel.

Intake Central
Review and manage tasks without leaving the dashboard
UX work led by Tessa Veto
Open full task details from any row
A dismissible flyout now gives users access to the information available in Task Overview directly from every task row. Users can review task details while keeping their dashboard and task list in view.
Complete common task actions in context
The preview supports marking tasks complete, reassigning them, changing due dates and statuses, setting acceptance decisions, and adding comments. Keeping these actions in the flyout helps client-agency users work through task queues with fewer page changes.
Build on a familiar, reusable pattern
The preview uses established flyout behaviors for loading and error handling, creating a consistent interface and a testable foundation for future API, action, and permission integration. This supports a modern software experience while helping users manage tasks more efficiently.
