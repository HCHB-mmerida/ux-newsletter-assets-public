Figma + GitHub skills plugin = rapid AI automation for legacy screen conversion to modern UI screens
UX work led by Wes Pallister and assisted by Ezequiel “Zeque” Dominguez
Turning legacy screens into a clearer starting point
UX is connecting Figma, AI-assisted workflows, and a GitHub repository of UI Skills to help teams convert legacy Citrix screens into modern web experiences more consistently.
Instead of beginning each conversion with a blank slate or relying on individual interpretation of legacy behavior, the UX team can use documented UX guidance, design-system components, and reusable interaction patterns as a shared foundation directly in Figma.
Giving AI the rules behind the interface
The UI Skills repository translates HCHB design-system guidance into reusable instructions that support screen conversion work. These skills help guide choices around layout, navigation, content hierarchy, feedback, accessibility, and approved UI components.
Figma provides the design context and visual direction, while the GitHub-based skills give AI and implementation teams a structured reference for applying that direction consistently. Together, they make design decisions more visible and repeatable throughout the conversion process.
Creating a stronger handoff from design to delivery
This connected workflow helps UX, Product, Engineering, and QA work from the same set of expectations. Teams can move from legacy screen analysis to modern design and implementation with clearer guidance on what should be preserved, redesigned, or replaced with an established web pattern.
The result is a more scalable approach to Citrix modernization—one that supports consistency across converted screens while reducing avoidable interpretation and downstream review cycles.

BackOffice multi-view: Keeping complex work connected
UX work led by Wes Pallister
Moving beyond legacy windows
During the BackOffice Citrix Elimination migration, UX identified that the legacy application’s multi-window, modal, and full-page navigation behaviors could not simply be recreated in a browser without introducing technical limitations and workflow risk.
UX designed Multi-view as a modern, web-native alternative: a workspace with adjacent panels, independent tabs, persistent page states, contextual entry points, and saved configurations. This gives users simultaneous access to related information while their primary task remains visible—preserving a critical legacy capability in a scalable model built for the web.
Keeping reference information within reach
Multi-view allows clinical coordinators and operational users to open supporting pages, patient information, and configuration screens alongside their active work instead of repeatedly navigating away and back. Contextual “Open in Multi-view” actions provide direct access at the point of need, while saved workspace configurations help users return to familiar arrangements.
This reduces repetitive navigation, re-orientation, and cognitive load in cross-referential workflows. Its impact will be assessed through task success and user confidence, along with changes in navigation steps, page changes, repeated searches, and context switching.
Testing a critical migration workflow early
Internal and external user interviews confirmed the need to access related information without losing workflow context. Their feedback continues to inform improvements to panel maximize-and-restore behavior, patient context, horizontal scrolling, flexible layouts, and multi-monitor support.
Testing before implementation helps surface capability gaps early, reducing the risk of avoidable rework, training needs, and support issues later in the migration. Ongoing evaluation will also track adoption, repeat use, saved configuration use, and remaining reliance on legacy-window workflows.
Establishing a pattern the platform can reuse
Multi-view creates a shared solution for Backoffice workflows that require cross-referencing. Rather than each team developing separate navigation workarounds, teams can reuse a consistent pattern for panels, tabs, context retention, and workspace management.
This supports modern software delivery by reducing one-off design and engineering solutions, while helping ensure the web platform is a capable improvement over the legacy experience—not a compromised replacement.

Finding the right path for multi-window work
UX work led by Lindsay Garlock
Testing the need behind legacy windows
Backoffice users regularly work across multiple windows and monitors to compare information without losing their place. To understand how that capability should translate to the web, UX tested two approaches: a Multi-view prototype with six users across five sessions, followed by a browser-tab solution with seven users across five sessions.
The research focused on the underlying workflow need—simultaneous access to related information—rather than assuming the legacy window model should be recreated as-is.
Identifying where Multi-view fell short
The Multi-view study confirmed that users value having multiple items open at once. However, users did not want that flexibility at the expense of seeing full content, exposing a core usability trade-off in the approach as designed.
This finding prevented the team from investing further in a solution that met the surface requirement for multiple windows but risked making complex work harder to complete.
Validating browser tabs as the stronger direction
The follow-up study found browser tabs to be the clearer and more usable path. All seven participants understood how to open a link in a new tab, either immediately or after a single right-click exploration. Six of seven participants used the tab bar easily once they located it, and the approach received an average confidence rating of 4.4 out of 5.
By validating browser tabs before development, UX gave the team evidence-based direction for a workflow pattern that affects many Backoffice users—reducing post-development rework risk and supporting a more predictable, scalable modernization process.

Care+
Client Meds Management: Making medication workflows easier to manage
UX work led by Carla Dall’Oste
Bringing medication work into one experience
UX designed Client Meds Management in Care+ to support adding, editing, searching, verifying, voiding, and reviewing medications. The experience also covers interactions, medication kits, unlisted and compounded medications, and review completion.
Shared forms, flyouts, status states, and actions align with existing Care+ patterns and the Care+ Design System, giving clinicians a more familiar workflow and giving Product and Engineering a clear model to build from.
 
 
 
Making actions and status easier to follow
Medication work can involve many clinical rules and visit-specific states. The designs clearly distinguish medication status, designations, verification, and interaction review so clinicians can see what is complete, what needs attention, and what to do next.
This reduces ambiguity during complex medication tasks and supports more confident clinical decision-making.
Designing for complex scenarios upfront
UX defined detailed workflow rules and edge cases before implementation, helping teams handle complex medication scenarios consistently instead of resolving them separately during development.
The experience can be evaluated through task completion, workflow effort, review completion, medication-record quality, and use of core actions such as verification, medication kits, and interaction review.
Creating a foundation Care+ can reuse
Client Meds Management establishes reusable patterns for medication forms, actions, clinical states, and review workflows. These patterns can support future Care+ medication capabilities while reducing one-off design and development effort.

Scheduling
Scheduling Notes: Keeping visit context inside Web Scheduling
UX work led by Ezequiel “Zeque” Dominguez
Making visit-specific notes easy to find
UX designed Scheduling Notes for Personal Care visits in Web Scheduling, allowing Service Coordinators to view and add visit-specific notes directly from the visit edit panel or visit card menu.
Visible indicators on visit cards and the calendar show when notes are available, helping coordinators identify relevant context without searching through separate communication channels.
Connecting context across visits
The experience also includes a patient-level Scheduling Notes history with author and timestamp details. This gives Service Coordinators a clearer view of scheduling-related context across visits when assigning, reviewing, or updating Personal Care schedules.

By centralizing notes within the scheduling workflow, the capability reduces context switching and communication gaps while supporting greater continuity in visit planning.

Intake Central
Hospice Election of Benefits: Closing a critical intake gap
UX work led by Tessa Veto
Improving hospice intake workflow
We’re improving the hospice intake workflow by introducing a new Election of Benefits tab, visible exclusively for the hospice service line. In many EHR platforms—including BackOffice—Election of Benefits information can be difficult to locate, despite its critical role in processing hospice admissions, maintaining regulatory compliance, and supporting accurate reimbursement for services provided. By placing this essential documentation in a dedicated, easy-to-access tab, hospice teams can work more efficiently, reduce administrative delays, and complete intake requirements with greater confidence.
Recognizing transitions at the point of intake
UX identified a parity gap for Hospice Election of Benefits. Unlike BackOffice, Intake Central did not allow users to identify a referral as a transition into HCHB, capture the HCHB Start Date, or manage Start of Episode independently when appropriate.
Without these capabilities in the intake workflow, transition-specific election details risked being incomplete, captured elsewhere, or corrected later.
Showing only the fields each referral requires
UX defined a new Election of Benefits tab that follows verified BackOffice rules. The experience distinguishes transitions into HCHB from standard New and Transfer referrals, exposing only the fields and behavior that apply to each referral type.
For transition referrals, users can capture the HCHB Start Date and maintain an independent Start of Episode. For standard referrals, Start of Care remains the source of truth. This conditional model helps prevent invalid or contradictory date information before it moves downstream.
Protecting data quality without adding complexity
Bringing transition-specific requirements into Intake Central reduces duplicate entry, manual follow-up, and downstream correction work for clinical and operational users. Required fields, date validation, and transition rules help ensure election details are complete before staging.
The solution also reuses established BackOffice models, validation, staging, and rehydration paths. This supports a more consistent web experience while limiting the need for one-off implementation logic.
Measuring a smoother transition workflow
As the capability is introduced, the team can evaluate completion of transition Election of Benefits records, time to capture required details, incomplete or abandoned saves, and validation issues. Additional measures can monitor whether saved values reappear correctly during editing, user confidence with the transition workflow, related support needs, and consistency with BackOffice behavior.
